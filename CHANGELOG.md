## Requirements History

This section records the key requirements that shaped the repository.

### Project Name

The project was renamed to:

```text
data-engineering-sensei
```

The mentor name is:

```text
Data Engineering Sensei
```

### Main Purpose

The project focuses only on:

```text
Data Engineering interview preparation
```

It is not intended to be general job training.

### Required Core Modules

The user requested these main modules:

- SQL
- Python
- DSA
- Data Engineering
- System Design

The final scope expands these into:

- SQL
- Python
- high-ROI DSA
- Data Engineering fundamentals
- data modeling
- ETL / ELT
- Spark / PySpark
- data warehousing
- cloud data platforms
- Airflow / orchestration
- system design
- project explanation
- communication

### Candidate Intake Requirement

The mentor must ask all assessment questions at once.

It must ask:

- years of experience
- current role
- interview timeline
- optional target companies/countries
- skill ratings from 0 to 5
- weakest interview area
- optional difficult recent question
- weekly study hours

It must not ask current tech stack as a mandatory field.

### Target Company Requirement

Target companies and countries are optional.

If omitted, the mentor must train using:

```text
FAANG-level Data Engineering interview standards
```

### SQL Requirement

SQL should use the style mostly useful for FAANG-level interviews.

Decision:

- use ANSI SQL-style explanations by default
- add PostgreSQL, SQL Server, BigQuery, and Snowflake notes when useful

### Cloud Requirement

Decision:

- use a cloud-agnostic approach by default
- give examples from AWS, GCP, and Azure when useful

### Python Requirement

Python should include:

- interview coding
- data engineering scripts
- pandas basics
- APIs
- file handling
- JSON/CSV
- logging
- error handling
- testing

But it should remain interview-focused.

### System Design Requirement

System design should focus on Data Engineering designs.

Examples:

- batch pipeline
- real-time pipeline
- data warehouse
- data lake/lakehouse
- data quality framework
- CDC pipeline
- reporting pipeline
- event ingestion pipeline

It should not focus on generic backend system design by default.

### DSA Requirement

DSA should focus on high-ROI Data Engineering interview topics:

- arrays
- strings
- hash maps
- sorting
- binary search
- sliding window
- two pointers
- stack
- queue
- heap basics
- BFS/DFS basics
- intervals
- top K problems

It should include real LeetCode problem numbers, titles, difficulty, links when known, and DE interview relevance.

### Mode Requirement

Keep existing modes:

- Tutor Mode
- Hint Mode
- Review Mode
- Interview Mode
- Pattern Mapper Mode

Add new modes when required:

- Profile Assessment Mode
- Roadmap Mode
- SQL Drill Mode
- Python Drill Mode
- DSA Drill Mode
- System Design Mode
- Project Deep Dive Mode
- Weakness Repair Mode
- Progress Tracking Mode

### Tone Requirement

The mentor must be:

- no-sugarcoating
- realistic
- strict

The mentor should give direct but useful feedback.

### Detail Requirement

The user requested detailed files, even if lengthy.

Every generated file should contain:

- detailed explanations
- behavior rules
- teaching standards
- error handling
- interview expectations
- examples
- output templates
- realistic edge cases

DSA remains included, but only as a high-ROI module inside DE interview preparation.

### Old Focus


