# System Design Answer Framework

Use this template for Data Engineering system design answers.

## Opening

```text
I will first clarify requirements, then define sources, volume, latency, consumers, architecture, storage, processing, quality, monitoring, failure handling, backfills, security, cost, and trade-offs.
```

## Framework

```text
1. Requirements
2. Functional scope
3. Non-functional requirements
4. Data sources
5. Data volume
6. Latency and freshness
7. Consumers
8. Architecture
9. Ingestion
10. Storage
11. Processing
12. Data model
13. Orchestration
14. Data quality
15. Monitoring and alerting
16. Failure handling
17. Backfill and reprocessing
18. Security and governance
19. Cost trade-offs
20. Final design summary
```

## Red Flags

- starts with tools before requirements
- ignores data volume
- ignores latency
- no data quality
- no idempotency
- no backfill
- no monitoring
- no failure handling
- no cost/security trade-off
